# S&P 500 Regime Prediction

Predicting **market regimes** of the S&P 500 a few days to a month ahead:

- **Bull / bear** — based on 20% drawdowns from a peak.
- **Calm / stressed** — based on 21-day realized volatility above the 80th percentile of the previous 5 years.

Each regime has a main label and a robustness label (`bear` / `bear_merged`, `stressed` / `stressed_fixed`); results must hold on both.

Our main goal is risk management: an early, well-calibrated warning that the market is entering a bear or high-stress period. We do not try to forecast exact prices.

**Headline result (walk-forward 1980–2021):** stress in the next 21 days is predictable. Logistic regression reaches PR-AUC 0.66 vs. 0.51 for "no change" and identifies upcoming stress on calm days about twice as well. Bear-market *starts* are not predictable; models only recognize bear markets once they are underway.

## Quickstart

Requires Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate          # on macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

The raw data is already in `data/raw/`, so one command processes everything:

```bash
python process_data.py
```

This cleans and aligns the raw CSVs, builds labels, targets and features, runs 21 checks (including a no-look-ahead test), and writes:

| Output | Contents |
|---|---|
| `data/processed/sp500_daily.{csv,parquet}` | Cleaned prices of all 4 series on one trading calendar |
| `data/processed/model_table.{csv,parquet}` | 15 features + regime labels + targets for h = 5 and 21 days |
| `reports/data_quality.csv` | Quality counts per raw series |
| [`reports/processing_summary.md`](reports/processing_summary.md) | Row counts, regime stats, every bear market found, feature start dates, check results |

Options: `--horizons 5 10 21` (prediction horizons), `--format csv|parquet|both`.

Then train and evaluate the baselines and models (walk-forward, about 2 minutes):

```bash
python run_models.py
```

This writes [`reports/model_results_main.md`](reports/model_results_main.md) and the timeline chart. The extra libraries it needs are `lightgbm` and `hmmlearn` (in `requirements.txt`).

To refresh the raw data with the latest prices (this overwrites `data/raw/*.csv`):

```bash
python -m sp500.data_download
```

Then open `notebooks/01_eda.ipynb`.

| `sp500tr.csv` | S&P 500 total return | `^SP500TR` | 1988-01-04 → 2026-10-23 | 9,776 | Bull/bear labels including dividends |
| `spy.csv` | SPY ETF | `SPY` | 1993-01-29 → 2026-10-23 | 8,492 | Real traded volume |
| `es.csv` | E-mini S&P 500 futures | `ES=F` | 2000-09-18 → 2026-10-23 | 6,590 | Futures moves (watch quarterly roll jumps) |

Committing the snapshot means everyone works on exactly the same data, even if Yahoo later revises or removes history. Details and known issues: [data/raw/README.md](data/raw/README.md) and [docs/02_data_understanding.md](docs/02_data_understanding.md).

The data comes from Yahoo Finance; S&P 500 index values belong to S&P Dow Jones Indices. It is included for non-commercial academic research only.

## Key rules (avoiding look-ahead bias)

1. Features use only data available at the close of day *t*.
2. Targets are labels shifted **forward** (`label.shift(-h)`); features are never shifted backward.
3. Volatility percentiles use only past data (the previous 5 years, shifted by one day).
4. Validation is walk-forward in time order, with a gap of at least *h* days between train and test.
5. **2022 onward is the final holdout.** Do not touch it during tuning.
